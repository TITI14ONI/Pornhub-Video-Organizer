# Politique de sécurité

## Versions prises en charge

Les correctifs de sécurité sont destinés à la dernière version publiée. Les anciennes versions ne sont pas maintenues; mettez à jour vers la dernière version disponible.

| Version | Prise en charge |
| --- | --- |
| Dernière version publiée | Oui |
| Versions antérieures | Non |

## Signaler une vulnérabilité

Ne signalez pas une faille exploitable dans une issue ou une discussion publique. N'incluez pas de données personnelles, de mots de passe, de jetons d'accès ou d'autres secrets.

Le signalement privé de vulnérabilités GitHub est actuellement désactivé pour ce dépôt. Le mainteneur doit l'activer dans **Settings → Code security and analysis → Private vulnerability reporting** avant que le bouton **Report a vulnerability** soit disponible dans l'onglet **Security**.

Une fois activé, utilisez le bouton **Report a vulnerability** de l'onglet **Security** pour envoyer un rapport privé. Si l'option n'est pas disponible, contactez le mainteneur par un canal privé déjà connu de vous. À défaut, ouvrez uniquement une issue non sensible pour demander un moyen de contact privé; ne publiez ni détails d'exploitation ni preuve de concept.

Dans le rapport privé, indiquez si possible la version concernée, les étapes permettant de comprendre le problème, son impact et une solution temporaire éventuelle. N'envoyez que les informations nécessaires.

Le mainteneur accusera réception et donnera des nouvelles dès que possible, mais aucun délai de réponse ou de correction n'est garanti. Il pourra demander des précisions, confirmer le problème ou expliquer pourquoi il ne peut pas être traité. Merci de laisser un délai raisonnable au mainteneur pour enquêter et préparer une correction avant toute divulgation publique.
